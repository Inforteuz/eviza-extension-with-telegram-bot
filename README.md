# eVisa Auto-Filler

Платный сервис для операторов, оформляющих Saudi eVisa (`visa.visitsaudi.com`):

* **Расширение Chrome/Edge**. Оператор перетаскивает фото паспортов, проверяет данные и портреты и нажимает ▶. Расширение само заполняет анкеты Individual или Group **до страницы оплаты**. Кнопку оплаты расширение не нажимает никогда: оплату выполняет оператор.
* **Telegram-бот**. Через него идут подключение расширения, баланс, пополнение (Click/Payme через Telegram Payments или перевод на карту с чеком), статистика, уведомления «заявка готова к оплате» и админ-команды.
* **Сервер** (Node.js). Держит бота, биллинг и API для расширения, распознаёт паспорт через AI (OpenAI) и вырезает портрет 200×200 (YuNet/OpenCV). Вся работа с изображениями идёт через Python/OpenCV, нативных Node-модулей нет. Поэтому сервер работает и на старых или виртуальных CPU без x86-64-v2 (SSE4.2), где готовые бинарники sharp/libvips и NumPy ≥ 2.4 не запускаются.

```
 Оператор ── Chrome/Edge ────────────────────────────────┐
   │  боковая панель расширения                          │ content script
   │  (загрузка, проверка, ▶/■)                          ▼
   │        │  Bearer-токен                  visa.visitsaudi.com (аккаунт оператора)
   │        ▼
   │   Сервер (HTTPS) ── OpenAI (текст паспорта)
   │   ├─ API /api/ext/*      ├─ Python/OpenCV (портрет)
   │   ├─ биллинг (SQLite)    └─ Telegram Bot API
   └── Telegram-бот: баланс, оплата, токен, уведомления
```

Форма заполняется в браузере оператора, под его аккаунтом Saudi. Сервер видит только фото паспорта (для распознавания) и не хранит его: изображение обрабатывается в памяти. Данные заявителей и портреты хранятся локально в расширении.

## 1. Что нужно владельцу сервиса

| Что | Где взять |
|---|---|
| Токен бота | @BotFather → `/newbot` |
| Telegram ID администраторов | @userinfobot |
| Приём оплаты | @BotFather → бот → **Payments** → Click Uzbekistan / Payme → *provider token* (валюта UZS). Или только карта: `CARD_NUMBER` |
| Ключ OpenAI | platform.openai.com, модель по умолчанию `gpt-4.1` |
| Сервер с доменом | VPS с Docker. A-запись домена указывает на сервер |

## 2. Запуск сервера

### Одной командой (рекомендуется)

На чистом Ubuntu/Debian VPS под root:

```bash
curl -fsSL https://raw.githubusercontent.com/Inforteuz/eviza-extension-with-telegram-bot/claude/affectionate-archimedes-yzozwx/deploy.sh -o deploy.sh
bash deploy.sh evisa.example.uz
```

Скрипт ставит Docker, клонирует код в `/opt/evisa` и спрашивает токен бота. Telegram ID администратора он берёт из сообщения `/start`, отправленного боту. Затем спрашивает ключ OpenAI и номер карты (оба необязательны), собирает архив расширения с вшитым адресом сервера и запускает всё с HTTPS. Архив раздаётся по адресу `https://<домен>/download/evisa-auto-filler.zip`, и бот показывает эту ссылку. Повторный запуск обновляет код и сохраняет `server/.env` и базу.

Если порты 80/443 свободны, HTTPS обеспечивает контейнер Caddy. Если на сервере уже работает nginx, скрипт его не трогает. Он добавляет отдельный сайт `/etc/nginx/sites-available/evisa-<домен>.conf` с проксированием на `127.0.0.1:8787` и получает сертификат через certbot. Если домен уже обслуживает другой сайт nginx, скрипт по умолчанию останавливается. Тогда есть три варианта: разместить сервис на том же домене по пути (`bash deploy.sh example.uz/evisa`), взять другой поддомен или заменить сайт (`REPLACE_NGINX_SITE=1`). В варианте с путём в существующий HTTPS-блок добавляется одна строка `include /etc/nginx/snippets/evisa-<домен>.conf;`. Остальной сайт и его сертификат не меняются. Перед изменением делается копия в `/root/nginx-backup/`. Если `nginx -t` падает, файл восстанавливается автоматически.

### Docker вручную

```bash
cp server/.env.example server/.env      # заполнить: токен, ADMIN_IDS, OPENAI_API_KEY, оплата
echo "DOMAIN=evisa.example.uz" > .env    # домен для Caddy/HTTPS
node extension/scripts/pack.mjs --server https://evisa.example.uz   # архив для /download/
docker compose up -d --build
docker compose logs -f server            # «eVisa server: ... · bot @имя_бота»
```

Caddy сам получает HTTPS-сертификат. Данные (SQLite) лежат в volume `evisa-data`, его нужно бэкапить.

### Без Docker

Нужны Node.js ≥ 22.13 (рекомендуется 24) и Python 3.10+.

```bash
cd server
npm ci --omit=dev
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env    # заполнить, PYTHON_BIN=.venv/bin/python
npm start
```

Перед сервером нужен HTTPS (nginx/Caddy), иначе расширение не подключится: кроме `localhost` принимаются только `https://`-адреса.

> Один токен бота — один запущенный экземпляр сервера. Бот работает через long polling. Если webhook включён, его надо отключить.

## 3. Сборка и раздача расширения

```bash
node extension/scripts/pack.mjs --server https://evisa.example.uz
# → extension/dist/evisa-auto-filler-1.0.0.zip (адрес сервера уже вшит)
```

Архив загружается в Chrome Web Store (unlisted) или раздаётся напрямую. Ссылку на него укажите в `EXTENSION_URL`, чтобы бот показывал её пользователям.

Установка без стора: распаковать zip → `chrome://extensions` (или `edge://extensions`) → «Режим разработчика» → «Загрузить распакованное» → выбрать папку.

## 4. Работа оператора

1. В боте: `/start` → «➕ Balansni to‘ldirish».
2. Открыть панель расширения (иконка на панели) → **Telegram orqali ulash**. В открывшемся боте нажать «✅ Ulash», и панель подключится сама. Другой способ — «🔑 Token olish» в боте и вставка токена в панель.
3. Войти на `visa.visitsaudi.com` своим аккаунтом. Код из почты и CAPTCHA вводит оператор.
4. Перетащить фото паспортов в панель (JPG/PNG, до 25 за раз). По каждому показываются портрет, данные и подсказки (профессия «None», семейное положение и т. п.): их нужно проверить.
5. ✓ (или ✎ → «Saqlash va tasdiqlash») подтверждает заявителя. Подтверждение привязано к точным данным и портрету: после правки его нужно повторить.
6. Выбрать **Individual** или **Group** (для группы указать название) → **▶ Boshlash**.
   * Individual: заявки заполняются по очереди. По умолчанию после каждой расширение останавливается на странице оплаты. Оператор платит и жмёт «▶ Davom etish». Остановку отключает настройка «har bir ariza to‘lovga yetganda to‘xtash».
   * Group: группа создаётся, люди добавляются через «Save & Add Applicant», в конце открывается общая страница оплаты.
7. Когда заявка готова к оплате, бот присылает уведомление.

Если сессия Saudi истекла, расширение просит войти и продолжает само сразу после входа в той же вкладке. При ошибке 1015/429 (лимит сайта) оно останавливается и ничего не повторяет автоматически.

## 5. Тарификация

* Плата берётся **за паспорт**, в момент успешного распознавания, если номер паспорта прочитан.
* Механика: сумма резервируется до запроса к AI. Если номер паспорта не прочитан или произошла ошибка, резерв возвращается.
* Повторное чтение того же заявителя, повторная загрузка того же паспорта в течение `DEDUPE_DAYS` дней и повторное вырезание портрета бесплатны.
* Заявитель, введённый вручную, оплачивается один раз при первом запуске заполнения (`/api/ext/activate`).
* Если баланс опускается ниже цены одного паспорта, бот предупреждает пользователя.

## 6. Команды бота

Пользователь: `/start`, `/ulash`, `/balans`, `/tolov`, `/statistika`, `/tarix`, `/yordam`, `/bekor`.

Администратор (только ID из `ADMIN_IDS`):

| Команда | Действие |
|---|---|
| `/admin` | сводка: пользователи, выручка, паспорта, ожидающие чеки |
| `/narx 7000` | новая цена за паспорт |
| `/qoshish ID 50000 комментарий` | начислить (или списать при `-5000`) |
| `/user ID` | карточка пользователя |
| `/kutilayotgan` | чеки, ждущие подтверждения |
| `/bloklash ID` / `/ochish ID` | заблокировать (отключает все устройства) / разблокировать |

Чеки переводов приходят администраторам с кнопками ✅/❌. Повторное нажатие ничего не начисляет, потому что зачисление идемпотентно.

## 7. Структура репозитория

```
server/                  бот + биллинг + API (Node, node:sqlite; изображения — Python/OpenCV)
  src/index.mjs          вход: HTTP-сервер + long polling
  src/bot.mjs            Telegram-бот (меню, оплата, админ)
  src/billing.mjs        баланс, резерв/списание, пополнения, статистика
  src/auth.mjs           токены расширения (хранятся хэшем), привязка через deep-link
  src/api.mjs            /api/ext/* для расширения
  src/recognize.mjs      AI-текст + портрет (независимо друг от друга)
  src/passport/          AI-схема, MRZ, YuNet-детектор, image.py (OpenCV-конвейер изображений)
extension/               Chrome/Edge MV3, сборка не нужна
  src/background.js      service worker: очередь распознавания, команды панели
  src/lib/runner.js      запуск Individual/Group, остановка, восстановление
  src/lib/page.js        Playwright-подобный page API поверх chrome.tabs
  src/flow/              сценарии заполнения Saudi eVisa (из исходного проекта)
  src/content/           content script: фиксированный набор DOM-операций, оплата запрещена
  src/panel/             боковая панель
e2e/                     браузерные тесты: Chromium + расширение + мок сайта Saudi
```

## 8. Разработка и тесты

```bash
npm ci --prefix server && npm ci --prefix e2e
pip install -r server/requirements.txt   # OpenCV + NumPy < 2.4
export PYTHON_BIN=python3                # Python с OpenCV (тесты изображений без него пропускаются)
npm test                     # server (40) + extension (45) unit-тесты
npm run test:e2e             # Chromium: привязка, чтение, Individual, Group ×3, вход, 1015
```

Для e2e нужен Chromium (`npx --prefix e2e playwright-core install chromium` или `CHROMIUM_PATH=...`). Мок сайта в `e2e/mock-saudi.mjs` повторяет подписи и id полей, на которых сценарии проверялись вживую.

## 9. Что изменено относительно исходного проекта

Исходный проект был локальным агентом для одного оператора: Playwright, Tampermonkey-скрипт, Windows-установщик и старая веб-панель. Отдельного расширения и платного режима в нём не было. Код остался в истории git (коммит `761e7c9` в `main`).

* Взяты и адаптированы проверенные части: сценарии заполнения Individual/Group с чекпоинтами и защитой от дублей, распознавание паспорта (AI + MRZ), вырезание портрета, модель заявителя, обработка 1015/429.
* Tampermonkey и localhost-мост заменены расширением MV3 с боковой панелью.
* DOM-операции приближены к семантике Playwright: скрытые элементы не совпадают, учитываются `aria-labelledby`/`title`, регистр при неточном поиске не важен. Иначе выбор года в календаре и дубли скрытых кнопок работали бы иначе, чем при живой проверке.
* Сервер, бот и биллинг стали многопользовательскими. Удалены старая Next.js-панель, Windows-установщик, Gmail/Tesseract-ветки и архивы.

## 10. Ограничения и что проверить вживую

* Реальный сайт Saudi в этой среде недоступен. Сценарии проверены на моке и перенесены из версии, которая 15–17.09.2026 доходила до оплаты вживую (Individual и группа из 2 человек). Перед запуском пройдите 1 Individual и группу из 3 человек на реальном аккаунте, не нажимая оплату.
* Страховка принимается только при сумме **95.00 SAR**. Если сумма другая, расширение остановится и попросит проверить.
* Сбор PDF готовых виз и режим «ребёнок + опекун» пока не реализованы.
* Docker-образ в этой среде не собирался: Docker Hub и apt были недоступны. Серверная часть проверена напрямую через Node.
* Защита оплаты в расширении работает на стороне клиента. Технически подготовленный пользователь может модифицировать распакованное расширение. Для обычных операторов этого достаточно. Более строгая защита потребует серверной выдачи сценариев.
